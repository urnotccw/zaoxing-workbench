# Product
## Platform
web
## Product Purpose
游戏美术五步生产工作流：设计背景、参考图、提示词模板、批量生成、审核返修。无限画布只是表达方式，顶部五步导航定位对应工作区，选中后才展开参数。
## Users
希望复用项目风格与参考图、减少逐角色重复输入的游戏美术。用户原项目星宿敌人提供问题背景；交付工具默认空白，不自动填入角色、图片、来源或任务。
## Brand Commitments
中文、简洁、易用。沿用石墨底色、纸白文字和旧黄铜主操作色。五步名称与主要动作保留文字；上传、缩放等采用一致的SVG图标与提示。
## Capabilities and Constraints
本地使用，不发布。画布平移缩放、节点拖动、自动排布、角色变量、引用图用途、模板展开批次、手动导入结果、尺寸和精确重复检查、人工选定、定向返修、IndexedDB保存与JSON备份。生图现已接入火山方舟 Seedream 5.0 Pro，支持试稿、逐张队列与参考图返修。附带本地Python服务，可用用户在本机填写的DeepSeek密钥调用真实Search与Chat接口做资料研究、特征提取、图像初筛；没有密钥时明确未连接，不伪造输出。在线参考图查找当前打开外部图片搜索，自动搜图未接入。AI初筛并非可靠的自动质量判定。
## Workflow Principles
用户只编辑一份背景、参考与模板；批次冻结这些要求。上游改变不覆盖旧结果，创建新批次。返修保留原图、原任务和新增修改/保留要求。用户上传和 Seedream 生成分别标明来源，新项目没有样例。导出包括完整素材与批次。API凭证不进入前端持久存储、项目文件或日志。
## Stack
原生HTML/CSS/JavaScript，独立HTML可离线体验。可选Python标准库本地服务仅监听127.0.0.1。

### 立绘与卡牌模板为什么这样设计

- **共同结构**：角色、识别特征、姿态、画风、背景语境、输出要求分别组合；参考图按用途约束。参考 Adobe 对主体、描述词、风格、颜色与光照的提示词建议，但具体生产规则由本项目用途推导。[Adobe 官方提示词指南](https://helpx.adobe.com/ca/firefly/web/work-with-images/generate-images/writing-effective-text-prompts.html)
- **立绘**：为后续排版和抠图准备单角色平面素材，默认完整全身、纯色底、轮廓清楚、关键部件不裁切。2:3画幅和约5%边距是可调整的项目初始方案，不是统一行业规范。纯白背景不等于透明通道，平面插画不等于可绑定拆层文件；拆层需按后续动画用途另做。[CLIP STUDIO 官方 Live2D 制作准备](https://tips.clip-studio.com/en-us/articles/2684)
- **卡牌**：输出供后续排版的插画底图；半身聚焦／全身叙事可选，主体在缩略尺寸下可读。卡框、名称和数值不交给生图模型直接绘制。暴雪美术总监的卡牌设计说明强调信息易读、卡面艺术与功能的关系，支持把插画与UI要求分开考虑。[Hearthside Chat: Art with Ben Thompson](https://hearthstone.blizzard.com/en-gb/news/13023802/hearthside-chat-art-with-ben-thompson-2-25-2014)
- **卡牌预留区**：顶部10%、底部20%只是演示模板初始值，应依据实际卡框调整，也可关闭；上述来源没有规定这些数值。尺寸按任务规格传入 Seedream，并校验模型范围；模型能否严格保留构图区域仍需效果验证。

### 五步之间保存什么

需求 → 带来源的角色特征及独立创作建议 → 按角色绑定的参考与统一画风 → 用途专属规则、可预览提示词和检查项 → 保存原要求的批次 → 实际结果、人工结论、AI疑点 → 保留原图与修改范围的独立返修任务。

模板切换改变画幅、构图规则与检查项；上游编辑只影响之后的新批次。项目JSON保存参考用途、角色绑定、输出选项和人工审核记录。缺少需求、角色特征、统一画风或必要变量时，会引导补充后再建批次。当前不会声称示例图片是新模板生成的结果。

### 界面层级
画布提供五步概览；节点下方的浮动卡片完成当前任务。设计背景分为输入需求与确认结果两个状态，角色详情按需展开。保留一条明确的主要操作，避免把填写、研究、确认混成一个长表单。此交互是结合用户反馈和上述披露原则的设计假设，需要用户实际试用。

### 参考证据范围
Liblib 的具体设定板布局以用户上传的两张截图为依据。没有查到足以核实小云雀对应画布交互的官方资料，因此不声称本版复现或验证了其工作流。颜色与字体沿用用户正在使用的版本，本轮没有更换视觉风格。

## 按实际制作任务细化（2026-10-17）

### 1. 背景研究与设计决定

初始只输入需求；已有文献和设定可选。检索事实、引用来源与原创建议分开保存，来源不足标为待核实。角色详情可细化轮廓、配色、材质、必须保留和避免出现的内容；对照表用于比较整组角色，发现完全相同的关键词时提示，但不把文字重复当成图像相似度。新增维度不是首次必须填写的表单。AI研究接口已真实调用成功，具体背景依据和设计建议质量仍需人工核对。

### 2. 图片取用与提示词引用

每张参考有用途（画风／身份／构图／姿态／材质）、使用角色、取用备注与来源记录。同一角色绑定多张身份参考时提示核对范围。第三步提供逐张勾选：只在可供该角色使用的候选中选择；取消不会删除原图片。已选图按显示顺序编号，自动生成「参考图1：文件名；仅参考用途；备注」等文本，同时任务保存图像ID列表。文本生成依据用户标签，并不声称已识别图中内容。

Adobe 官方资料支持以参考图控制视觉风格，但不同服务的参数能力不相同。因此本工具先保存用途和图像对应关系，未接入的生图服务不显示虚假的强度滑块或保证风格锁定。[官方风格参考说明](https://helpx.adobe.com/firefly/web/work-with-images/generate-images/set-styles-for-image-generation.html)

### 3. 模板是制作要求，不只是姿态名称

| 立绘选项 | 使用场景 | 额外要求与审核重点 |
|---|---|---|
| 沿用角色设定 | 已有明确动作 | 保留原动作；缺少动作时使用可读展示姿态 |
| 站姿展示 | 图鉴、角色介绍 | 重心与支撑合理、四肢与主体不粘连 |
| 坐姿／休憩 | 对话、性格表达 | 接触与承重、关节关系；座椅需明确指定 |
| 动态／战斗 | 技能展示、动作探索 | 动作线、受力、透视、持握与前方空间 |
| 悬浮／飞行 | 飞行单位、灵体 | 动势协调，不为满足飞行新增翅膀 |
| 蹲伏／蓄势 | 警戒、潜伏、攻击准备 | 低重心、支撑点、关节与关键识别点 |

预设优先于角色旧动作，切回「沿用」恢复原动作；非人角色按物种调整，不能机械套用双足人体。动态姿态的动作线、重力、透视和结构考虑参考 Adobe 专家教程；上表的场景分类是本工具的产品设计。[Adobe 动态姿态教程](https://www.adobe.com/uk/creativecloud/illustration/discover/dynamic-poses.html)

卡牌在半身／全身和信息区设置之外，增加角色叙事、技能瞬间、角色主视觉用途。三视图仍独立使用中立姿态与正侧背对应关系；动作模板不应污染建模或结构参考。

### 4. 批量是可追溯的变化

可选择本批参与角色，提前显示角色数×方案数。同条件抽样保留相同提示词，不伪造随机种子效果；姿态系列依数量展开站、坐、动态、悬浮，各自拥有提示词和审核项。系列模式不套用一个姿态的自定义细节。预览与复制对应当前选中的方案。角色身份、设计约束和画风保持不变。上游调整不覆盖已有任务。

### 5. 审核、对照与返修

文件规格、相同图像数据与人工检查分开；姿态特有问题随模板保存。结果可在同批并排对照，灰度切换只辅助观察明暗，不提取虚假剪影、不自动判断设计优劣。原任务与返修任务均保留，可同时查看。记录问题后返修带入问题、身份特征与设计约束，用户可调整修改范围。

### 默认空白与数据保存

取消默认样例和演练入口。更新首次打开时，将旧浏览器项目留作本机迁移备份，当前项目切为空白；之后正常恢复用户新建内容。此迁移只执行一次。项目导入导出保留参考选择、来源、角色参与范围、姿态、变体和审核记录。

### 接入生图后仍需完成的验收

Seedream 接入已实现图片编号顺序传参、尺寸范围校验、逐张队列、停止后续、状态恢复和明确重试；相关逻辑测试通过。单张真实生图成功，但参考组合、连续批量、结构准确性与返修质量仍需用用户实际任务验证。局部蒙版编辑尚未实现。稳定性、风格一致性和提效幅度需用同一组真实任务对照测试，不能仅凭界面完整度下结论。

### 浮动编辑卡片
点击卡片操作后，在当前节点下方展开紧凑的浮动编辑卡片；不占满底部，不缩短画布高度。卡片随画布定位，接近屏幕边缘时限制在可视区域内，内容独立滚动；关闭后恢复概览。窄屏保留两侧间距。五步内容、默认空白与保存规则保持一致。


## 五步生产闭环扩展（2026-10-17）

本节取代此前仅串接表单和任务的行为说明。功能仍为本地 Demo，不代表已证明模型稳定性或提效比例。

1. **设定确认**：已有设定可直接填写；AI 研究结果的原创建议先待处理，采用后才进入制作参数，或排除。背景依据可标为用户原创、用户已核对出处、待核实。无出处不能标已核对。每次确认保存设定及来源；编辑后确认状态失效。确认设计不等于核实历史事实。
2. **参考配置**：项目共用／角色专用与素材类型分别设置。三视图排除姿态图片。相同用途多张图须指定主参考或各自取用范围，属于规则提醒，非图像冲突检测。可填写不要取用的部分和来源。AI 图片分析走真实接口，返回建议后由用户采用；没有密钥或接口不支持图片时明确失败。
3. **制作规格**：保留原模板及多种姿态；增加全身／半身、表情、固定项、允许变化项、真实透明背景交付要求。提示词按需展开。区分多个角色生产和单角色衍生，后者只允许选择一个角色。纯色底不是透明通道；图像导入检测透明像素，未实现自动抠图。
4. **试稿到批量**：先为每个角色创建试稿，可再试一版并保留已有方案。确认角色特征、画风和用途后选为基准；同角色本批只有一张选中基准。所有参与角色确认后，才可按数量／姿态系列展开批量。改变数量和系列方式不要求重复批准相同试稿；改变设计或规格需要新试稿。跨用途试稿可引用仍匹配身份与风格要求的既有基准。批量任务冻结参考图片、基准、设定、规格和提示词。
5. **审核交付**：保留尺寸、比例、重复图片和人工逐项检查；增加分层问题记录（位置、依据、修改目标、保留项、程度、处理结论）。返修创建独立任务并保留父任务与原图；原问题不因创建返修自动消失。人工检查通过、无未处理问题且规格符合后才能选定交付。交付可从全部批次选定素材，导出原始图片与 JSON 清单的 ZIP；清单包含冻结要求、基准关联、来源和审核记录。

### 本轮验证与限制

- Node 逻辑检查覆盖确认失效与恢复、参考类型隔离、规则冲突、试稿门槛、基准传递、返修关系、交付门槛和透明规格。ZIP 用 Python 验证 CRC、中文文件名及原始字节保持不变。
- 浏览器从空白完成手动设定 → 确认参考 → 创建试稿，并验证重载后确认状态保持；桌面与 390px 窄屏检查浮动编辑卡片，页面无横向溢出。
- DeepSeek 研究、参考分析和视觉审核已于2026-10-17通过真实接口测试；参考分析与视觉审核使用构造图片，不宣称通过真实游戏美术质量验收。图片上传和完整含图流程主要由逻辑测试覆盖。
- Seedream 生图已接入并完成单张实测；自动搜图、自动抠图和局部蒙版编辑仍未接入。问题定位当前为文字记录。没有自动语义相似度评分；人工和 AI 疑点仍分开。
- 新项目仍为空；测试内容仅存在独立测试服务的浏览器存储，未打包进交付入口。

独立复核修正：批量复用同时核对已选试稿与图片身份；切换基准会创建新批次。返修原图作为独立参考进入 AI 审核、参考数量限制和交付清单，并可在任务详情查看。透明交付仅适用于立绘／卡牌，审核条件随之调整；三视图保持白底设定板。对应回归测试已通过。

### DeepSeek 真实接口连接验证（2026-10-17）
